# 2026-09-15 — `--hint` deleted by its own rule; 0.3.1

## The release chain lost its GitHub App

The 0.4.0 candidate's release chain required a GitHub App as the only actor allowed to create `v*`
tags, with its private key in a `release` environment. None of it existed, and it could not be
created without a browser and a new credential, so production was blocked on infrastructure. For a
single-maintainer repository the App defended against nothing an admin-restricted ruleset does not:
a compromised admin can edit rulesets either way. The owner chose the simpler design. The maintainer
creates a lightweight tag at a CI-green `main` commit and dispatches `release.yml` from `main`;
`release-policy.sh verify` requires the tag to name exactly the dispatch SHA; only `draft-release`,
gated by the main-only `release` environment, has `contents: write`. Rulesets `release-tags`
(creation/update/deletion of `refs/tags/v*`, bypass: repository admin role) and `main` (deletion,
non-fast-forward), plus the `release` environment with a `main` branch policy, were created through
the API and read back. Four planted workflow regressions (write grant moved, tag trigger, environment
removed, tag re-check removed) each fail the selftest.

duplicated effect statistics in a frozen instrument, an issue-14 `decision` field (would need a rerun
of the public evidence for a signal now deleted).

## Autoreview (Codex, P3, frozen clone at 615c5e0)

Three P2 findings, all accepted. (1) Changing `release.yml` on main did not retire its historical
tag-triggered copies: a tag at an older commit still ran them. The workflow moved to
`release-dispatch.yml` and the old `release.yml` identity is disabled in repository settings;
consumers now verify the new signer path, and the selftest fails if the old path reappears.
(2) The draft foreign-asset guard read the asset list through a process substitution, so a failed
query looked like an empty draft; it is now `release-policy.sh check-draft-assets` with the query
captured separately and a planted control that fails on the old form. (3) A shallow sibling clone
reports its boundary commit as a root and escaped clone exclusion; shallow checkouts are now
`unknown` and excluded, the runner refuses a shallow project, and the control uses synthetic
repositories so it also runs in CI's shallow checkout. None of the one-shot's 37 on-disk candidate
repositories was shallow, so its result is unchanged.
