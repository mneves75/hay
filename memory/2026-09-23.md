# 2026-09-23 — 0.3.2: eight divergences the differential test could not see

## What the review found

A full review (standards, spec, security, Rust correctness, then Codex autoreview at P3) of
everything since v0.3.0. The measurement kit and release chain held up; the shipped binary did not.
Eight places where `hay` answered a different question than the corresponding `rg` invocation, all
quiet wrong answers, all invisible to `differential-test.sh` because every one of its 32 cases
passed PATH `.` to a walked directory:

- piped stdin ignored (`cmd | hay x` searched the cwd, usually exit 1);
- a binary file named as PATH exited 1 (rg converts NUL there and quits only while walking);
- `-g` rooted at PATH instead of the cwd — wrong in both directions;
- unranked `-v -m N` printed more than N, and `-m` dropped after-context (sink-return stop instead
  of the searcher's `max_matches`, which under `-v` means "resume after the next match");
- non-UTF-8 lines and file names printed lossily;
- a non-UTF-8 argument panicked, exit 101;
- a nested checkout's `.git` searched under `--hidden`.

Ten new PATH/stdin cases: 42/42 on 0.3.2, and the 0.3.1 binary fails all ten — the failing control.

## Two of my own mistakes, caught before they shipped

- **Pruning `.git` as a directory broke a documented contract.** The first VCS fix used
  `filter_entry`, which runs before overrides, so `--hidden -g '.git/**'` returned nothing where rg
  searches `.git` — the parity SECURITY.md promises. Caught because SECURITY.md said so and the
  matrix was probed against rg, old hay and new hay. The fix is unanchored file-level globs
  (`!**/.git/**`) added before user globs, so a later include still wins.
- **A vacuous pass in the harness I had just extended.** `sed` in the caller's locale rejected the
  Latin-1 line on both sides; both outputs were empty; empty equals empty. `LC_ALL=C` on sed and sort.
- Also: I rebuilt `target/release/hay` twice while `measure-mrr --compare` was reading it. Killed
  and rerun on a frozen binary (hash recorded before and after). Never rebuild under a running
  measurement.

## The trade-off taken on stdin

ripgrep's heuristic reads stdin whenever it is a pipe and no PATH is given, and that is a known
hazard in harnesses that hand children an open pipe (ripgrep #2582, #2806, #2838). Before 0.3.2
`hay` was immune — by being wrong for `cmd | hay x`. Parity won: the invariant is ripgrep's
behaviour, the hazard is one harness authors already handle for rg, and the old behaviour was a
silent wrong answer. HOWTO and MANUAL now say to pass a PATH from scripts.

## Behavioural re-measurement

934 paired queries, 12 repositories, re-harvested repo-rooted corpus. 0.3.2 and 0.3.1 give
IDENTICAL figures (control run with the 0.3.1 binary on the same corpus and harness): MRR rg 0.2087
→ hay 0.4286 (+0.2199, repo-clustered CI [0.1917, 0.2487]), top-10 0.3919 → 0.7323. Gate 0.4328 /
0.7721, still FAIL. Below the published 0.4437 / 0.7849 because the corpus changed, not the binary —
which is why the control run was worth its hour.

## GitHub served an empty asset list

After publishing, `GET /releases/tags/v0.3.2` (and `-beta1`) returned `assets: []` for over half an
hour, while `/releases/{id}`, `/releases/{id}/assets`, GraphQL and the download URL all served ten.
`gh release download` reads the by-tag endpoint, so `brew-formula.sh` failed closed (exit 2) —
correctly. It now fetches from the public download URL, the exact URL the formula records, behind a
`fetch_asset` seam the selftest stubs (without the stub the selftest would 404 on its fake tag and
pass for the wrong reason). Checksum-manifest and attestation checks unchanged.
