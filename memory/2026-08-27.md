# 2026-08-27 — v0.2.0: the first ranking change, and the gate it still fails

## The criticism that started it

> "It does not pass its own criterion. The README reports MRR 0.404 against ripgrep's 0.266
> (p<0.0001) but records that it *fails its own ship gate* — median 0.381 against a target of 0.50.
> And that is in its own domain, code."

Correct, and the only two answers available were: move the gate, or make the ranker better. The
gate did not move.

## What was built

**File interleaving (the large one).** Every relevance judgment in this project is per *file* —
what an agent does with a result is open a file — while MRR counts result *lines*. A module with
forty matching lines therefore pushed the file that declares the symbol to line-rank forty-one.
`hay` now round-robins the ranked list by file: pass one carries each file's strongest line, pass
two its next-strongest. Nothing is re-scored, the sequence of distinct files is unchanged (so `-l`
is byte-identical), and the behavioural top-10 rate moved **18.8 points on its own**.

The lesson worth keeping: the biggest retrieval gain this project has ever measured came from
noticing what the unit of an answer is, not from understanding code better.

**A graded `word` signal.** Pre-registered in `DESIGN-hay.md` before any Rust was written
("exact case/word match > substring — free from the matcher") and never implemented. `+1.0` for a
whole identifier, `+0.5` when the query starts one, nothing when it is buried (`auth` inside
`oauthToken`). Worth +0.010 to +0.022 MRR on each public corpus.

Note the trap avoided: a *binary* whole-word signal was measured and DELETED on 2026-08-19
(−0.001). This is not that signal returning unexamined — it is graded rather than binary, and it
was measured on three public corpora rather than on the evaluation set. Both facts are in
DESIGN-hay.md, because "we tried that and deleted it" is exactly the kind of thing that gets
quietly re-added.

## The decision that cost the gate

A **filename signal** — a bonus for a file whose own name is the query — is the highest-weighted
field in every published lexical code retriever (BM25F; Sourcegraph's post-embeddings Cody). It
was implemented, and simulated against the private evaluation corpus it was worth **+0.033 median
MRR**, which would have brought the gate from 0.444 to within 0.02 of passing.

On the development sets it earned +0.008 (openclaw), +0.000 (ripgrep), −0.002 (alamofire) and
**−0.0136 on SWE-Explore**, the one public agent-shaped benchmark. Deleted.

This is the first time the firewall cost something it wanted, and it is the entry that matters:
the evaluation set does not get a vote on what ships, *especially* when it says the thing you want
to hear. The public definition-finding benchmark is structurally blind to a filename signal (its
queries are function names), which is a real argument for the signal — and an argument is not
evidence. If it is to come back, it needs a public dev set whose queries look like the ones agents
type, and SWE-Explore already said no.

## Result of the one confirmation run

951 paired queries, 12 repositories, frozen binary, both retrievers rerun together:

| | 0.1.4 | v0.2.0 |
|---|---|---|
| paired MRR (rg → hay) | 0.266 → 0.404 | 0.258 → **0.458** (+0.1995 [0.1754, 0.2243]) |
| top-10 | 46.1% → 60.0% | 44.9% → **77.1%** (+32.2 pts) |
| nDCG@10 | 0.373 → 0.503 | 0.358 → **0.501** |
| queries where hay is worse | 235 (25%) | **115 (12%)** |
| **GATE** median MRR / top-10 | 0.3810 / 0.5916 | **0.4437 / 0.7849** — still FAIL |

The rg column is recomputed, not copied: these are live working trees and they moved since
2026-08-20.

**The excuse was checked and is not available.** An oracle ranking any answer file first scores
**1.00** on this corpus — every judged answer is reachable in both retrievers' output — so nothing
about the corpus or the metric makes 0.50 unattainable. The gap is ranking. First-position rate:
31.7%. What remains is dominated by broad greps (`test`, `timeout`, `catch`, `node_modules`) whose
next-opened file is a function of the task rather than the term; stratifying the gate around those
*after* seeing them fail would be the exact move this repo exists to refuse.

## Two defects found on the way

1. **`hay` crashed on any non-ASCII query.** Both identifier scans advanced one *byte* past a
   rejected occurrence, so a query whose first hit sat inside a word sliced into the middle of a
   multi-byte character: `hay -F -e 'éé'` over a line containing `aéé` exited 2 with "ranking
   thread panicked" — on a search ripgrep answers. Present since the scan was written; found by
   reading the new code's sibling, reproduced from the command line before being fixed.
2. **A safety check was deleting 22% of the external evidence.** The SWE-Explore archive reader
   rejected any repository tarball containing a symbolic link, so 21 of the 97 committed instances
   stopped scoring on a clean machine. Links are now dropped individually and counted — never
   written to disk, which is what the check was for — and ripgrep does not follow symlinks anyway,
   so the extracted tree is identical for the measurement. Instrument error 13: **every safety
   limit is a potential silent sampler.**

The second one is the more useful lesson. The payload had been printing `repoSkipped: 22` the
whole time; invariant 7 (count truncations, never absorb them) recorded it and nobody read it.
A counter nobody reads is not a gate.
