# 2026-08-22 — 0.7.0: the release that changed no ranking, on purpose

`hay` 0.7.0, pushed as `219137b`, then `ce6ef6f`. **No ranking code changed**, and the release is
built so that claim is checkable rather than asserted: differential-test stayed at 0 differing,
and the behavioural gate numbers (median-repo MRR 0.3810 / top-10 0.5916, n=952) are byte-identical
to the 0.6.0 confirmation run.

## The advisors gutted the cleanup plan, correctly

The cycle opened with a KISS/DRY cleanup plan: decompose `run()`, consolidate the `emit_*`
family, merge the two definition heuristics in `score.rs`, extract a TS util module. Three of
four parallel reviewer agents came back AMEND with the same message: **the duplication does not
exist** — prior ablation passes had already harvested this codebase, and every remaining "copy"
encodes a distinct contract pinned by tests. Executing the original plan would have grown files
while calling it cleanup, inside the highest-risk functions in the repo. What survived review:

- one `window()` for context arithmetic that lived identically in reader and emitter (drift there
  would read-unprinted or print-unread lines no match-parity test catches);
- one `hits_marker()` for the three path-class tables — the SOURCE table re-spelled the predicate
  with a `format!("/{d}")` allocation per path per marker on the hot scoring path;
- one `is_ident_char()` across three definition-heuristic sites.

The parse_args double-eval micro-fix was attempted and **reverted by my own gate**: dropping the
match guards made unknown short flags silently no-op instead of falling through to the
unknown-option error — precisely invariant 5's quiet-wrong-answer class. The reviewers had said
"not worth a diff on its own"; they were right twice.

## One real defect found by checking the help text against the code

`-l --json` emitted a bare `type:"begin"` record per file — violating hay's own documented JSON
contract ("only match and context messages") and producing a `begin` with no matching `end`. An
empirical check against ripgrep initially suggested the opposite fix (rg emits full JSON events for
`-l`), but the repo documents the deviation deliberately, twice; the branch was the bug, not the
help text. `-l` now wins over `--json`; pinned by a new contract test because no test covered the
combination.

## The benchmark page became a published surface — and got treated like one

`benchmark-report.ts html()` upgraded from markdown-mirror to a report page: inline-SVG charts of
the Δ-MRR intervals (**filled mark = both statistical tests agree**; hollow = the bootstrap says
yes but randomization disagrees, or the interval touches zero — exactly what the tables refuse to
bold), top-10 shares, search-time ratios vs ripgrep on a log scale, and a Feynman-style explainer
distilled from `BENCHMARK_FEYNMAN.md`. Design identity unified with the new `MANUAL.html`
("instrument ledger": warm paper, hay-gold, ruled texture) after an image-generation pass turned
out to have no backend available — the re-imagination shipped as implemented code instead.

Then four advisor agents reviewed the whole diff before release. Three delivered; their findings:

- **Blocker**: the top-10 chart divided a stored fraction by 100 again — all bars rendered ~5px
  wide while labels said 90–100%. A chart visually asserting the opposite of the table next to it.
  Fixed; selftest now pins bar geometry, not just `<title>` presence.
- **Major, proven end-to-end with a PoC**: `evidence/benchmark.json` is not gitignored, gets
  re-rendered into committed HTML, and `Bun.file().json()` enforces nothing — tampered numerics
  (`queries`, `rankCap`, `medianRank`) flowed raw into the page as stored XSS. Fix:
  `validatePayload()` at load, fail-closed on any non-finite numeric, covering both HTML and
  markdown renderers; `esc()` hardened to `'`.
- **Major ×3 in `benchmark-corpora.sh`**: empty corpus-list output degraded into benchmarking
  whatever happened to be on disk with exit 0 (guard died with its own data source); custom
  `BENCH_CORPORA` verified one tree while benchmark.ts measured another; user `--sample` was
  silently ignored because `flag()` takes first occurrence. All fixed; plus dir/URL validation
  before the script's `rm -rf`.

The fourth agent (stats/design lens) errored mid-run; its slice was covered manually via
screenshot passes in light/dark/mobile and by re-checking the filled/hollow rule against
`detected()` on real data.

## Paired comparisons no longer depend on sample luck

Evidence files now record each corpus's exact query symbols, and `benchmark.ts --queries-from`
replays them — so a before/after isolates the code change from sample luck. Verified live against
this repo-as-corpus: record → pin → identical symbols; renamed declaration → loud counted skip
("1 skipped: no longer declared exactly once"), never silent. `parsePinned` fails closed on
unusable pin lists, including the empty case the first draft let through.

## Operational notes

`benchmark-corpora.sh` ran its first full production cycle end-to-end: cloned linux/openclaw/
alamofire fresh (an earlier external incident had deleted the corpora directory mid-session —
never attributed), measured five corpora (~2h40m), rendered the report, deleted only its clones.
One transient failure mode met and handled: github's smart-HTTP path hung mid-handshake while web
endpoints responded fine; `http.lowSpeedLimit/lowSpeedTime` now converts that into exit 2 instead
of an eternal hang.
