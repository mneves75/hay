# 2026-08-23 — 0.1.1: the release CI wrote

The 0.1.0 release shipped with CI that had never executed (the repo was private). Its first
public runs failed, and every item in 0.1.1 came from reading those failures rather than
re-running them:

- **The MSRV claim was false.** The committed lockfile pins `globset 0.4.20` / `ignore 0.4.33`,
  which declare `rust-version = "1.88"` — upstream ripgrep now sets MSRV metadata on its crates
  and tracks recent stable. Our "MSRV 1.85" compiled locally only because the local toolchain is
  1.98; the dedicated MSRV job was the only thing positioned to notice, and it did, on its first
  run. Bumped to 1.88 in the manifest, the CI job pin (comment now says to keep them in sync),
  the installer gate, AGENTS.md, MANUAL, and the site chip.
- **A generated file was stale.** `benchmark-feynman.html` in the tree lacked the live-companions
  paragraph its generator emits — the staleness gate (`git diff --exit-code` after regeneration)
  caught it on first execution. Regenerated.
- **The installer had three defects nobody had hit.** The advertised one-liner piped to `sh`
  while the script uses `pipefail` (dash rejects it); the "installing to" message appended `/bin`
  to a path already ending in `/bin`; and — found by codex autoreview at P3, verified real —
  the install dir was derived from `dirname $(command -v cargo)`, which is wrong for Homebrew or
  distro cargo. Now derived by cargo's own resolution order (`CARGO_INSTALL_ROOT` →
  `CARGO_HOME` → `~/.cargo`), and confirmed end-to-end by running the live installer from main:
  installed 0.1.1 into `~/.cargo/bin`, smoke test green.
- One more CI round: the runner's shellcheck fails on info-severity SC2015 that the local one
  passed — the smoke-test `&& … || true` became a plain `if`. Lesson: adding a file to a linter
  gate means the CI linter's version decides, not yours.

Ship chain: commit → push → CI green (**first fully green public run**: 32662935816, all seven
jobs) → `v0.1.1-beta1` pre-release (tarball downloaded back and smoke-tested, installer verified
live) → `v0.1.1` Release with sha256 in the notes → gh-pages updated (index chip + version,
MANUAL/benchmark refreshed to release editions, Feynman links kept on the site's `.html`
convention) → all four live URLs verified 200 with the new content.

Blocker #5 (cross-platform CI unverified) is closed. The durable lesson is the one this repo
already teaches in another costume: a gate that has never executed is a claim, not a gate —
both first-run failures were real defects sitting under a green-looking local workflow.
