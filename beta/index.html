Same matches. Better order. hay is a ranked grep for coding agents. Likely definitions come first, then one result from each file. Complete searches preserve the normalized ripgrep match set; caps or read errors mean incomplete results.

The search order moves. The illustrative hay validateSession . fixture has six matches in four files. The declaration moves from fourth to first, with all six matches retained. Four different files appear before any file’s second result. Read both complete result lists above.

Source 0.4.0 features. hay --find sesison . finds exact names, substrings and an adjacent typo. hay --mcp --root . manually starts stdio MCP with grep, find_files and multi_grep. Both use live files. MCP searches stay within explicit Git repository scopes; there is no persistent index or search history.

Evidence and limits. The historical hay 0.3.0 definition-finding benchmark is dated 2026-08-28. The table above gives all four corpora, query counts, MRR values, absolute differences and 95% intervals shown in the film. Definition finding is hay’s home turf, not agent-task success. The documentation track has zero detected wins and four detected regressions. The private behavioral gate still fails and was not rerun for these source-only features.
